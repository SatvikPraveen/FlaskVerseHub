# Retrieval research notes

FlaskVerseHub's search is an information-retrieval (IR) system built from
first principles so that each modelling choice can be *measured*. This note
records the design, the evaluation methodology, the current results and the
known limitations, in the style of an experimental write-up.

## 1. Research questions

1. Does classical morphological normalisation (Porter stemming) improve
   effectiveness when queries and documents use different inflections?
2. How sensitive is BM25 to its two free parameters, `k1` (term-frequency
   saturation) and `b` (document-length normalisation), on a collection with
   skewed document lengths and keyword stuffing?
3. Does the probabilistic BM25 family outperform the vector-space TF-IDF
   cosine baseline, and does the BM25+ lower bound (Lv & Zhai, 2011) help?

## 2. System under test

| Component | Implementation | Reference |
|---|---|---|
| Analyzer | regex tokeniser, lower-casing, stop list, Porter stemmer | Porter (1980) |
| Index | in-memory inverted index; postings as NumPy arrays; field boosts folded into tf and length | Manning, Raghavan & Schütze (2008), ch. 1–2 |
| BM25 | `idf · tf·(k1+1) / (tf + k1·(1 − b + b·dl/avgdl))`, non-negative idf | Robertson et al. (1994) |
| BM25+ | BM25 with additive `δ` on the saturation term | Lv & Zhai (2011) |
| TF-IDF | `lnc.ltc` cosine in SMART notation | Salton & Buckley (1988) |

The stemmer is verified against the worked examples in Porter's paper
(`tests/research/test_analysis.py`). Ranker invariants (non-negative, finite
scores; zero for non-matching documents; saturation; the effect of `b`) are
checked with Hypothesis property tests.

## 3. Evaluation methodology

### 3.1 Collection

Public test collections are large, licensed and slow for continuous
integration, so experiments use a **seeded synthetic collection**
(`experiments/corpus.py`) whose relevance judgements are exact by
construction:

* 12 topics × 4 subtopics; each topic owns a Zipf-distributed vocabulary and
  each subtopic a small focused vocabulary.
* A document has a primary (topic, subtopic) and, with probability 0.35, a
  secondary topic whose words act as *hard negatives*.
* Graded relevance for a query on (t, s): primary (t, s) → grade 3;
  primary topic t, other subtopic → grade 1; otherwise 0.
* Emitted words are inflected (`-s`, `-ing`, `-ed`) at rate 0.35 while queries
  use base forms, making stemming measurable.
* Lengths are log-normal (σ = 0.6) and 5 % of documents repeat one topic word
  20–60 times, stressing `b` and `k1`.

The default configuration (`experiments/configs/default.yaml`) yields 600
documents and 96 queries. Everything derives from a single seed, so the
collection, the runs and the statistics reproduce exactly.

### 3.2 Metrics

Implemented in `app/search/metrics.py` and unit-tested against textbook
values:

* Binary: P@5, P@10, R@10, F1@10, MRR, MAP — a document counts as relevant
  when its grade is ≥ 3 (TREC-style threshold), so the marginally relevant
  grade-1 documents are hard negatives for binary metrics.
* Graded: nDCG@10 with gain `2^g − 1` and log₂ discount (Järvelin &
  Kekäläinen, 2002) over the full graded judgements.

### 3.3 Statistics

* Every aggregate is a mean over queries with a **95 % percentile bootstrap
  confidence interval** (2 000 resamples, seeded).
* Each system is compared with the baseline using a **two-sided paired
  bootstrap test** over per-query scores (5 000 resamples). Bold p-values in
  the report are < 0.05.

### 4.1 Interpretation

* **Stemming matters (RQ1).** Every `nostem` configuration is significantly
  worse than its stemmed counterpart (p < 0.001). The gap is driven by the
  inflection rate; set `inflection_rate: 0` in a config to make it vanish,
  which is a useful sanity check of the methodology.
* **Length normalisation matters more than k₁ (RQ2).** Disabling length
  normalisation (`b = 0`) is significantly worse (p = 0.019) because stuffed
  and very long documents are no longer penalised, whereas `b = 1.0` and
  `k₁ = 1.2` are statistically indistinguishable from the baseline and
  `k₁ = 2.0` shows a small negative effect at the significance boundary
  (p ≈ 0.05). This mirrors the common finding that `b` is the parameter
  worth tuning first.
* **BM25 beats TF-IDF; BM25+ is a wash (RQ3).** The `lnc.ltc` baseline trails
  BM25 significantly on nDCG@10. BM25+ is numerically the best system but
  not significantly different from BM25, as expected when queries are short
  and documents rarely omit query terms entirely.

### 4.2 Threats to validity

* **Synthetic language.** Words are random syllable strings with artificial
  Zipf and inflection structure; absolute numbers are not comparable with
  TREC collections and effect sizes may be larger or smaller on real text.
* **Short queries.** Queries have one to three terms; results for verbose
  queries, where BM25+ and tf saturation matter more, are not covered.
* **Single seed per report.** The CIs quantify query sampling variance, not
  collection sampling variance. Run with several `--seed` values to assess
  the latter.

## 5. Reproducing and extending

```bash
make experiment                                              # default config
python -m experiments.run_retrieval_benchmark --seed 7       # another collection
python -m experiments.run_retrieval_benchmark --config my.yaml --out /tmp/out
```

To add a ranker, subclass `app.search.rankers.Ranker`, register it in
`RANKERS`, add a property test in `tests/research/test_index_and_rankers.py`,
reference it in a config and re-run the benchmark. To study a collection
property, add a parameter to `experiments.corpus.generate_corpus` and expose
it through the `corpus:` section of the config.
